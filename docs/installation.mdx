# Installation

## Requirements

- git
- Python 3.9+ with SQLite FTS5 (`/usr/bin/python3` on macOS works)

These tools are optional:

- [gitleaks](https://github.com/gitleaks/gitleaks) 8.25 or newer. If `install.sh` does not find it, it downloads a
  pinned version into `~/.cache/retroagent/gitleaks` and checks its sha256.
- The GitHub CLI `gh`. The setup uses it to create the data repo, and the pages routine uses it for its secrets.
  Without `gh`, create a private repo on github.com and give its URL to the setup.

## Let your agent do it

Paste this prompt into Claude Code or Codex. The agent clones the code and does the same steps as the `setup` skill.
It asks you one question at a time.

```text
Set up retroagent on this machine for me: https://github.com/gabe4coding/retroagent
1. If ~/.retroagent does not exist, clone the repo there.
2. Read ~/.retroagent/skills/setup/SKILL.md and follow it step by step. Use ~/.retroagent/bin/kb while `kb` is
   not on my PATH yet.
3. Ask me one question at a time, and show me each command before it creates a repo, pushes or changes anything
   outside this machine. My data repo must be private.
4. install.sh also installs the Claude Code and Codex plugins: tell me if it prints a WARNING, and at the end
   remind me to start a new session (and, in Codex, to trust the retroagent hook with /hooks).
5. Never ask me for a token or a secret: I type those in my own terminal.
```

## With the Claude Code plugin

```
/plugin marketplace add gabe4coding/retroagent
/plugin install retroagent@retroagent
/retroagent:setup
```

The `setup` skill asks one question first: **Recommended** or **Customize**.

- **Recommended** shows one list of commands. After you approve it, the skill creates a private
  `retroagent-data` repo, installs retroagent and starts the first sync. It also writes the summaries in the
  background.
- **Customize** asks one question for each item:
  - the data repo and the name of this machine (its `host`)
  - the first sync and the summaries
  - automatic syncs and updates
  - semantic search, cloud sessions and the [pages routine](./pages-routine.mdx)

After the setup, start a new session. Claude Code loads the plugin, its skills and its hook only in a new session.
If `~/.local/bin` is not on your `PATH`, add this line to your shell file (`~/.zshrc` or `~/.bashrc`):

```bash
export PATH="$HOME/.local/bin:$PATH"
```

To finish or change the setup, run the skill again at any time.

## By hand, or for Codex only

```bash
git clone https://github.com/gabe4coding/retroagent ~/.retroagent
gh repo create <you>/retroagent-data --private          # or use an existing private repo
~/.retroagent/install.sh --repo git@github.com:<you>/retroagent-data.git --host <unique-name>
kb backfill --recent 14       # the sessions of the last 14 days, in about a minute; no push
kb backfill                   # every other session; the first push; then automatic syncs start
kb backfill --summaries       # 3-line summaries with Haiku (slow; uses your Claude quota)
```

After the first sync, `kb find` works. When `kb backfill` completes with no errors, it turns on automatic syncs. Until
then, each new session starts `kb backfill` again in the background. If a backfill stops, the next one continues from
where it stopped. To decide yourself, run `kb enable` or `kb disable`.

If you use Codex, open Codex once and trust the retroagent hook with `/hooks`.

### What `install.sh` does

1. It clones the data repo into `~/.retroagent-data`. The `--root DIR` option changes that folder.
2. If it does not find gitleaks, it downloads a pinned version and checks its sha256.
3. It writes `~/.config/retroagent/config.json` (see [Configuration](./configuration.mdx)). If the config has no
   `auto_sync` value, it sets `auto_sync: false` and `auto_sync_pending: true`. The first full `kb backfill` then
   turns on automatic syncs.
4. It pushes the base files that the data repo does not have (`README.md`, `AGENTS.md`, `CLAUDE.md`, `.gitignore`).
   It pushes them in one commit.
5. It installs the Claude Code and Codex plugins from the code clone. If you added the `retroagent` marketplace from
   GitHub, it replaces that marketplace with the code clone. Then the plugin, Codex and the shell use the same code.
6. It links `kb` into `~/.local/bin`.
7. It builds the search index.

If `auto_sync` is already `true`, `install.sh` starts a sync in the background. Otherwise it starts no sync. To
prevent that sync, add `--no-sync`.

You can run `install.sh` again at any time. It keeps your other config keys.

## One host name per machine

Each machine must have its own `host`. The default is the short hostname. Two machines with the same `host` write
the same folders.

Each machine has a random id in `.kb/machine-id`. The first sync commits a copy of this id as
`sessions/<host>/.machine-id`. If a machine has a different id, a sync or install on it stops with
`host '<host>' belongs to another machine`.

- Do not delete `.kb/machine-id`.
- If a machine wrote `sessions/<host>` before retroagent added these markers, run `install.sh --force-host` once on
  it. This claims the host.
- After a new data clone or a lost `.kb/machine-id`, run `install.sh --host <host> --force-host` on the machine that
  owns the host. The command copies the committed marker into `.kb/machine-id`, and the machine gets its id back.
- Run `install.sh --force-host` only on the machine that owns the host. Two machines with one id write the same
  folders.

## Update

- `kb update` pulls the code clone (fast-forward only). Then it runs `install.sh` again for the plugins, the `kb`
  link and the config.
- `kb enable updates` makes the background sync do the pull once a day instead. It also refreshes the plugins when
  the plugin version changes, or when Claude Code loads another version than the code clone. If a refresh fails, the
  run of the next day tries again.

Claude Code sessions load the plugin from a cache. Only `claude plugin update` copies a new version into it, and
`install.sh` runs this command each time. Start a new session to load the new version. `kb status` shows a warning
when Claude Code loads another version than the code clone.

Both commands run the latest `main` of the code repo. To know what changed, read the new commits on `main`.

All entry points run the same copy of the code:

- `~/.local/bin/kb` links to the code clone.
- The cached copy of a plugin (Claude Code, Codex) forwards to the code clone in the `code` config key.
